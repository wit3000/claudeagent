# ТЗ: Triple-Pass Text Reviewer — довести до продакшена

## 0. Контекст (обязательно к прочтению)

Сервис проверяет русскоязычный текст в **три независимых LLM-прогона** и
сводит результат в консенсус.

- Прогон 1 — «Технический вычитчик»: факты, логика, стиль.
- Прогон 2 — «Логик-придира»: только логика и противоречия.
- Прогон 3 — «Читатель без контекста»: читательские сбои.

Каждый прогон обязан цитировать текст дословно, иначе замечание отбрасывается
как галлюцинация. Дефект, подтверждённый 2–3 прогонами, попадает в «высокий
приоритет», найденный 1 прогоном — в «низкий». Категория, где отвечающий за
неё прогон ничего не нашёл, считается чистой.

Целевой пользователь — редактор, который вставляет русский текст в браузере
и получает отчёт на русском. Хостинг — **Hugging Face Spaces (Gradio SDK,
free CPU basic или ZeroGPU)**. LLM-провайдер по умолчанию — **Groq**
(бесплатный, без карты). Провайдер должен переключаться через env без правки
кода.

Репозиторий: https://github.com/wit3000/claudeagent
Ветка для разработки: `claude/multi-layer-text-review-kdpbjf`

## 2. Известные проблемы, которые надо решить

### 2.1. Ненадёжность деплоя через веб-UI HF

Копипаст файлов через HF Files ломается на тройных бэктиках и длинных
файлах. Кодер должен избавить пользователя от этого пути.

**Требование:** написать `scripts/deploy_hf.py` — CLI, который:
- принимает `--space <user/name>` и `--hf-token <token>` (или берёт из
  `HF_TOKEN` env);
- через `huggingface_hub.HfApi.upload_folder` заливает в целевой Space
  файлы: `app.py`, `requirements.txt`, `README.md`, папку `src/`;
- игнорирует `__pycache__`, `.pytest_cache`, тесты, `.env*`, `data/`,
  `logs/`, `out/`;
- пишет коммит-сообщение (`--message`, по умолчанию `deploy: <sha>`);
- ретрайит на сетевых ошибках (2 попытки, экспоненциально);
- выводит финальный URL Space после успеха.

Инструкция в `README.md` меняется: один шаг вместо копипаста —
`python scripts/deploy_hf.py --space theklyou/triple-pass-reviewer`.

### 2.2. Провайдер LLM должен быть сменным без правки кода

Сейчас `llm.py` жёстко завязан на Groq. Нужно переключение через
`LLM_PROVIDER=groq|openai|anthropic|gemini|openrouter`, чтобы пользователь
мог мигрировать без правки .py.

**Требование:**
- Создать `src/reviewer/providers/` с модулями `groq.py`, `openai.py`,
  `anthropic.py`, `gemini.py`, `openrouter.py`. Каждый экспортирует класс
  с интерфейсом `async def call(system, user, max_tokens) -> LLMResponse`.
- `llm.py` превратить в фабрику: читает `LLM_PROVIDER` (по умолчанию `groq`),
  подгружает нужный модуль, отдаёт единый `LLMClient`.
- Ключ читается из env, имя переменной берётся из провайдера (`GROQ_API_KEY`,
  `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`,
  `OPENROUTER_API_KEY`).
- Модель по-прежнему через `MODEL_ID`, дефолт задаётся провайдером.
- Все зависимости провайдеров в `requirements.txt` — extras не нужны, они
  все лёгкие.
- Добавить в UI бейдж с текущим провайдером и моделью (маленькая подпись
  под заголовком, читается из env при старте).

Юнит-тесты: замокать HTTP-клиент каждого провайдера, проверить, что
фабрика выбирает нужный класс, что `call` возвращает `LLMResponse` с
корректными полями.

### 2.3. Улучшить качество на слабых моделях

На Llama-3.3-70b (Groq) модели часто галлюцинируют и уплывают в
английский. Промты уже на русском, JSON-контракт есть. Нужно усилить.

**Требование:**
- В `orchestrator.py` при валидности <70% (`valid_findings / (valid + hallucinated) < 0.7`)
  сделать один автоматический **retry-with-nudge**: тот же промт + короткое
  добавление в user-сообщение «Твой предыдущий ответ содержал цитаты,
  отсутствующие в тексте. Каждую цитату проверь дословно перед тем как
  включить в JSON.». Если после retry всё ещё >30% галлюцинаций — оставить
  как `unreliable`.
- В `parser.py` расширить нормализацию цитаты: помимо кавычек и пробелов,
  игнорировать разные виды тире (`—`, `–`, `-`), ё↔е, регистр. Это уменьшит
  ложные отбраковки на моделях, склонных к «микроправкам».
- Добавить в `passes.py` в каждом системном промте явный запрет:
  «Не переводи и не адаптируй цитату — вставляй ровно как в тексте, включая
  знаки препинания и переносы строк.»
- Юнит-тест в `test_parser.py`: цитата с изменённым тире («—» → «-») теперь
  засчитывается.

### 2.4. Fallback между провайдерами

Один провайдер может отказать (лимит, downtime). Сейчас пайплайн падает
целиком, если модели нет.

**Требование:**
- Env `LLM_FALLBACK_CHAIN=groq:llama-3.3-70b-versatile,openrouter:meta-llama/llama-3.1-70b-instruct:free`
  (список `provider:model` через запятую).
- Оркестратор пробует первый; если `LLMClient.call` падает с
  `APIStatusError`/`RateLimitError`/`ConnectionError` после ретраев —
  переключается на следующий из цепочки. Логирует, куда перешёл, и это
  попадает в warnings отчёта на русском.
- Дефолт цепочки — только первый провайдер из `LLM_PROVIDER`, чтобы
  ничего не поменялось для тех, кто цепочку не задал.

### 2.5. Персистентность и share-link

Сейчас на HF Gradio-фронте нет истории и нет прямых ссылок на конкретные
отчёты. Есть заготовка в `src/reviewer/web/` (FastAPI + SQLite +
`/r/<job_id>`), но она не работает в Gradio-режиме.

**Требование:** для Gradio-режима реализовать легковесную историю:
- SQLite в `data/reviewer.db` (путь через env `DB_PATH`, по умолчанию
  относительно рабочего каталога; на HF писать в `/tmp/reviewer.db` —
  disk на free-тарифе эфемерный, это нормально для теста).
- Каждый отчёт сохраняется под `job_id` (12 hex).
- В Gradio добавить `gr.State` + отдельный tab «История» с таблицей
  последних 30 прогонов (текст ID, время, high/low count, кнопка «открыть»).
- Прямая ссылка: URL с query-параметром `?job=<id>`, при загрузке страницы —
  подтянуть тот отчёт. Реализуется через `gr.load_url` или чтение
  `window.location.search` в JS-callback.

### 2.6. Индикация версии промтов и модели

В отчёт добавить в подвал одной строкой:
`Провайдер: <name> · Модель: <MODEL_ID> · Промт: <PASS_VERSION>`.
Это помогает воспроизвести результат и понять, что менялось между прогонами.

### 2.7. Лимиты и защита от абьюза

Даже приватный Space стоит защитить от случайного цикла и от подмены.

**Требование:**
- `MAX_TEXT_CHARS` (уже есть, 20 000) — оставить, добавить более понятное
  сообщение с подсказкой разбить текст.
- Добавить in-memory rate-limit на процесс: не более 30 проверок в час
  на процесс (env `PROCESS_MAX_PER_HOUR`, дефолт 30). Пробегает и на
  Gradio, и на FastAPI.

## 3. Что НЕ делать

- Не менять концепцию «три независимых прогона, консенсус 2-из-3».
- Не добавлять четвёртый прогон.
- Не удалять существующие модули (`web/`, `cli.py`) — они могут использоваться
  в другом сценарии.
- Не менять `PASSES` (`p1/p2/p3`) и разрешённые категории — от этого
  зависит парсер.
- Не удалять существующие тесты. Только добавлять новые.

## 4. Требования к коду

- Python 3.11+.
- `ruff` пройти без ошибок (можно добавить конфиг в `pyproject.toml`, режим
  умеренный — E, F, I).
- `pytest -q` — все существующие + новые тесты зелёные.
- Никаких print-отладок в prod-коде (кроме одной строки `[boot]` при
  старте). Логирование — через модуль `logging`, JSON-строки.
- Не хранить секреты в репозитории, только env.
- Комментарии в коде — только там, где WHY неочевиден. Русские комментарии
  разрешены в промтах и UI-строках, всё остальное — на английском.
