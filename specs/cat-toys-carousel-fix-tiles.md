## 1. Слайдшоу «не работает» — починить

Диагноз (подтверждено чтением кода): разметка ок (у `photo-1` есть
`slide--active`), CSS ок (`.slide{opacity:0}` / `.slide--active{opacity:1}`),
JS-логика в `initPhotoCarousel()` корректна по структуре. Проблема — **тайминг
старта**: сейчас после наведения ждём `PHOTO_HOVER_DELAY_MS` (2с) и только потом
запускаем `setInterval` (ещё 2с) → **первая смена слайда только на ~4-й
секунде**, из-за чего кажется, что ничего не происходит.

**Требование:**
- Первое переключение должно происходить **на отметке задержки (≈2с после
  наведения)**, а не через 2+2с. Т.е. когда истёк `PHOTO_HOVER_DELAY_MS` —
  **сразу показать следующий слайд**, и дальше продолжать каждые
  `PHOTO_INTERVAL_MS`.
  Реализация: в колбэке `delayTimer` сперва `show((current+1)%N)`, затем
  завести `setInterval(... show(next) ..., PHOTO_INTERVAL_MS)`.
- Сохранить: старт по `mouseenter`, полную остановку и возврат к первому слайду
  по `mouseleave`, защиту от дублей таймеров, тач-фолбэк (`hover: hover`),
  очистку таймеров (без утечек).
- Перепроверить путь переключения класса `.slide--active` трассировкой: при
  наведении слайды реально сменяются по кругу 1→2→3→4→1 с кроссфейдом.
- Если по ходу найдётся иная реальная причина «не листает» — починить её тоже
  (напр. слушатель не на том элементе, ранний `return`, опечатка). Отметить в
  отчёте, что именно было.
- Замечание (не для правки кодом, для отчёта): на реальной странице тяжёлые
  PNG (~2 МБ) с `loading="lazy"` могут не успеть подгрузиться к моменту показа
  слайда → мелькание пустоты. В превью с лёгкими картинками это не проявляется.
  Решается оптимизацией фото (отдельное решение заказчика) — код не трогаем.

## 2. Подсветка текстовых плиток при наведении лазером

Сейчас подсветка (`setHot` → класс `laser-hot`) вешается только на `a,button`
(в `onOver`/`onOut` фишки курсора). Заказчик хочет, чтобы **текстовые плитки
без ссылок тоже подсвечивались** под лазером.

- Плитки-цели: **карточки категорий `.card`** и **карточки «Почему» `.why-card`**
  (по желанию так же плитки-пилюли `.hero__usp li` — если смотрится ровно;
  на выбор Лупы, задокументировать).
- Расширить `onOver`/`onOut`: помимо `a,button` определять наведение и на
  плитку-цель (`closest(".card,.why-card")`), и вешать/снимать на ней
  класс подсветки.
- **Разделить два вида подсветки** (чтобы плитки не читались как кликабельные):
  - у `a,button` (`.btn`/`.fab`) — прежняя «лазерная» подсветка `laser-hot`
    (красноватое свечение + подъём/scale) и увеличение точки `dot--hot`
    остаются как есть **только для кликабельных**.
  - у текстовых плиток — **отдельный, более мягкий класс** (напр.
    `tile-hot`): деликатная подсветка в фирменной гамме (мягкая тень/лёгкое
    свечение `--brand`/усиление `--shadow`, небольшой подъём `translateY(-2px)`),
    БЕЗ красного «лазерного» ореола и без увеличения курсорной точки
    (`dot--hot` для плиток НЕ ставить — плитка некликабельна).
  - Реализация в JS: в `setHot`/обработчиках различать тип элемента (кнопка/
    ссылка vs плитка) и вешать соответствующий класс; хранить текущий
    подсвеченный элемент(ы) без «залипания» и мигания при переходе между
    соседними плитками (по аналогии с текущей логикой `relatedTarget`).
- Оформление классов — в CSS (JS только переключает классы). Учесть
  `prefers-reduced-motion`: для плиток убрать scale/резкие переходы, оставить
  мягкое свечение.
- Снимать подсветку плиток при уходе курсора с плитки, уходе за окно и
  деактивации фишки (как для кнопок).
- Тач/мобайл: фишки курсора нет — плитки не подсвечиваются (норм), обычное
  поведение не трогаем.

## 3. Критерии приёмки
- [ ] При наведении на фотогалерею слайды видимо листаются: первая смена ~на 2с,
      далее каждые 2с по кругу с кроссфейдом; уход курсора — стоп и возврат к
      первому; тач — статичный первый кадр.
- [ ] Текстовые плитки (`.card`, `.why-card`) подсвечиваются под лазером мягкой
      фирменной подсветкой (без красного лазерного ореола, без увеличения точки).
- [ ] Кнопки/ссылки сохраняют прежнюю «лазерную» подсветку и увеличение точки.
- [ ] Нет «залипшей» подсветки; снимается при уходе курсора/за окно/деактивации.
- [ ] reduced-motion: у плиток без резкого scale; touch — без подсветки.
- [ ] Фишка котёнка-курсора, погоня, глаза, кнопки — не сломаны; адаптив цел.
- [ ] `python -m pytest -q` зелёный; `node --check script.js` ок; консоль чистая.
- [ ] Саморевью `code-review` пройдено, находки разобраны.
