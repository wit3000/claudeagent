# ТЗ: Фотокарусель игрушек в hero (автопролистывание по наведению)

Итерация 10. Заменить плейсхолдер «Фото игрушек Хулимяо» в hero на **слайдер из
4 фото** с автопролистыванием по наведению курсора.

Файлы: `landing/index.html`, `landing/styles.css`, `landing/script.js`. Ветка
`claude/pupa-lupa-agents-nw54ho`. Не ломать: фишку котёнка-курсора, подсветку
кнопок, логотип, шрифты, секции, адаптив. `python -m pytest -q` зелёный.

## 1. Ассеты
Фото кладёт заказчик в `landing/assets/photos/` (папка с README уже создана):
`photo-1.jpg … photo-4.jpg` (порядок 1→2→3→4). Формат — JPG (README допускает
PNG — тогда поменять расширение в массиве `PHOTOS`).

## 2. Разметка (index.html)
Заменить текущий `.hero__visual` (плейсхолдер со `<span>`) на контейнер-слайдер:
- Контейнер `.hero__gallery` (сохранить прежние габариты/скругление/рамку от
  `.hero__visual` — те же пропорции 16:8, `border-radius`, максимальную ширину).
- Внутри — 4 `<img class="slide">` с `src="assets/photos/photo-1.jpg"` …
  `photo-4.jpg`, у каждого осмысленный `alt` («Игрушка Хулимяо — фото 1» и т.д.),
  `loading="lazy"`, `decoding="async"`. Первый слайд — активный.
- `role`/`aria-label` на контейнере («Фотогалерея игрушек Хулимяо»).
- Плейсхолдер-подложка: оставить прежний штрих-фон `.hero__visual` как фон
  контейнера, чтобы **до загрузки фото** (или если картинка не подгрузилась)
  блок выглядел осмысленно, а не пусто/сломанно.

## 3. Стили (styles.css)
- Слайды абсолютно спозиционированы внутри контейнера, заполняют его
  (`object-fit: cover`, `width/height:100%`), наложены друг на друга.
- Активный слайд — `opacity:1`, остальные `opacity:0`; плавный кроссфейд
  `transition: opacity ~.6s ease` (класс `.slide--active` ставит JS).
- Контейнер: `position:relative; overflow:hidden`, прежние пропорции/скругление.
- `prefers-reduced-motion: reduce` — кроссфейд без плавности (мгновенно), либо
  без анимации; авто-смена см. §4.

## 4. Поведение (script.js) — автопролистывание по наведению
- Конфиг вверху (рядом с остальными): `PHOTO_HOVER_DELAY_MS = 2000` (задержка
  старта после наведения), `PHOTO_INTERVAL_MS = 2000` (интервал смены),
  `PHOTOS`/кол-во слайдов из DOM.
- Логика: на `mouseenter` контейнера — запустить таймер `PHOTO_HOVER_DELAY_MS`
  (2с); по его срабатывании начать авто-смену слайдов каждые `PHOTO_INTERVAL_MS`
  (2с): следующий = `(i+1) % N`, переключая класс `.slide--active`.
- На `mouseleave` — остановить (снять и таймер задержки, и интервал), вернуться
  к первому слайду (или оставить текущий — на выбор, но без «залипших»
  таймеров; предпочтительно вернуть к первому для предсказуемости).
- Никаких утечек: очищать таймеры/интервалы; повторные наведения не плодят
  несколько интервалов.
- **Тач/мобайл:** ховера нет — показывать первый слайд статично (авто-смену не
  запускать). Использовать проверку `matchMedia('(hover: hover)')` /
  `(pointer: fine)` по аналогии с фишкой котёнка. Контент виден и без ховера.
- Взаимодействие с фишкой котёнка-курсора: слой курсора `pointer-events:none` —
  наведение на галерею срабатывает штатно; не конфликтовать со слушателями
  курсора (свои слушатели вешать на элемент галереи, а не на document).
- reduced-motion: авто-смену можно оставить (это не «болезненная» анимация), но
  переход делать мгновенным; либо, если проще, при reduced-motion не
  автолистать — на выбор, задокументировать.

## 5. Крайние случаи
- Фото ещё не загружены (404): плейсхолдер-подложка держит вид; `alt` виден;
  ничего не «ломается». Лендинг в прод — только после загрузки фото (TODO).
- Одинаковые габариты фото не гарантированы: `object-fit: cover` обрезает под
  контейнер, без искажения пропорций.

## 6. Критерии приёмки
- [ ] В hero вместо плейсхолдера — галерея из 4 `<img>` (photo-1..4), первый
      активен; прежние пропорции/скругление контейнера сохранены.
- [ ] При наведении курсора: через 2с стартует автопролистывание, слайды
      сменяются каждые 2с по кругу, плавным кроссфейдом.
- [ ] Уход курсора — авто-смена останавливается, таймеры очищены, без утечек.
- [ ] На тач/мобиле — статичный первый слайд, без авто-смены; контент виден.
- [ ] До загрузки фото блок выглядит осмысленно (подложка), не сломан.
- [ ] Фишка котёнка-курсора и подсветка кнопок не затронуты; адаптив цел, без
      горизонтального скролла.
- [ ] Конфиг (`PHOTO_HOVER_DELAY_MS`, `PHOTO_INTERVAL_MS`) вынесен и легко
      правится; массив путей к фото — в одном месте.
- [ ] `python -m pytest -q` зелёный; `node --check script.js` ок; консоль чистая.
- [ ] Саморевью `code-review` пройдено, находки разобраны.
