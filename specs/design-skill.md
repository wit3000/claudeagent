# ТЗ: Скилл дизайн-решений «design-matrix» (матрица задача → типографика/палитра/сетка + типографика поверх обложек)

## 0. Контекст

Пользователь хочет скилл, который автоматически подтягивается, когда он просит
«сделай красиво», и даёт модели системные правила: как делать качественную
вёрстку и как подбирать шрифты/цвета **в зависимости от типа задачи**. Область
широкая: лендинги, веб-интерфейсы, артефакты Claude, презентации/слайды и —
отдельно — **обложки музыкальных альбомов** (типографика и композиция поверх
готового изображения, подбор шрифта под жанр/мэссадж).

Разобрано до написания ТЗ: запрос частично пересекается с уже существующими
скиллами. Новый скилл оправдан **только** в части, которой сейчас нет ни в одном
скилле — **переиспользуемая матрица «тип продукта/задачи → типографика +
палитра + сетка + плотность + моушн»**, единый **чек-лист качества вёрстки** и
**гайд по типографике поверх изображения (cover art)**. CSS-полировку
существующего UI и философию небанального бренда дублировать нельзя — это уже
есть.

Этот скилл — **справочный/знаниевый** (reference skill): он даёт модели готовую
таблицу решений и правила, а не меняет контракт существующих скиллов.

Решения пользователя по открытым вопросам (учтены в этом ТЗ):
1. Размещение — **глобально**, `~/.claude/skills/design-matrix/`.
2. Область — лендинги, веб-интерфейсы, артефакты, презентации/слайды, **обложки
   альбомов** (доработка подгружаемых изображений).
3. Дефолтного бренд-стиля **нет** — навык подбирает под задачу.
4. **Claude Design нужен** наравне с Claude Code (с оговоркой про проверку, см.
   разделы 3 и 4).

## 1. Что уже есть и что нельзя ломать

Проверено по файлам (не выдумано):

- `/.claude/skills/web-visual-polish/SKILL.md` — триггерится **буквально** на
  «сделай красиво», «сделай стильно», «освежи дизайн». Строгий контракт: **только
  CSS, поведение/DOM/шрифты/CDN не трогать**, полировка существующего интерфейса.
  Один фиксированный набор токенов независимо от типа задачи.
- `/.agents/skills/frontend-design/SKILL.md` — небанальный визуальный дизайн
  нового UI, уход от шаблонов, бренд «под бриф». На английском. **Не** владеет
  фразой «сделай красиво». Принципиально **без** готовых матриц.
- `artifact-design`, `dataviz` — дизайн артефактов и графиков/цветов.
- `write-spec` — шаблон ТЗ. `anthropic-skills:skill-creator` — создание и
  оптимизация скиллов, в т.ч. `description` под авто-триггер.

**Нельзя сломать:** авто-триггер `web-visual-polish` на «сделай красиво» для
CSS-полировки существующего интерфейса. Новый скилл **не перехватывает** этот
сценарий (см. 2.3). Код в `src/`, `landing/` и существующие спеки не трогаем.

## 2. Задача

### 2.1. Где реальная дыра, а где дубль

- **Дубль, не делать:** «CSS-полировка существующего интерфейса» —
  `web-visual-polish`. «Небанальный бренд нового UI под бриф» — `frontend-design`.
- **Реальная дыра (ради неё скилл):** (а) переиспользуемая матрица «тип задачи →
  типографика/палитра/сетка/плотность/радиусы/тени/моушн»; (б) единый чек-лист
  качества вёрстки с кириллицей; (в) гайд «типографика и композиция поверх
  обложки/изображения» — такого нет ни в одном скилле.

### 2.2. Структура пакета скилла

Создать через механику `skill-creator` (см. 2.6) глобально:

```
~/.claude/skills/design-matrix/
  SKILL.md                 # frontmatter + короткое тело (см. 2.3, 2.4)
  references/
    matrix.md              # матрица архетипов UI/веб (см. 2.4)
    cover-art.md           # типографика/композиция поверх обложки (см. 2.5)
    quality-checklist.md   # чек-лист качества вёрстки (см. 2.4)
```

Крупные блоки выносим в `references/` (прогрессивное раскрытие): тело `SKILL.md`
короткое, модель читает reference по ссылке, когда нужно.

### 2.3. Frontmatter и разведение триггеров (критично)

`name: design-matrix`. `description` — одно поле, на русском, по формуле
skill-creator («что делает» + «когда применять» с триггер-фразами). Обязательно:

- Сценарии: дизайн/вёрстка **с нуля** или **по ТЗ**; подбор **шрифтов и цветов
  под тип продукта/аудиторию/жанр**; «какой шрифт / палитра / сетка подойдёт для
  <X>»; **оформление обложки альбома / типографика поверх изображения**; «сделай
  красиво», **когда нужно создать новое оформление или выбрать стиль под задачу**
  (а не полировать готовый CSS).
- Триггер-фразы: «сделай красиво», «сделай стильно», «подбери шрифты», «подбери
  палитру/цвета», «какой шрифт под…», «оформи под <тип>», «сделай дизайн под
  <аудиторию>», «сделай обложку», «оформи обложку альбома», «типографика на
  обложке», «текст поверх картинки».
- **Явная граница в тексте description:** «Не для чистой CSS-полировки уже
  существующего интерфейса без смены контента (это `web-visual-polish`). Дополняет
  `frontend-design`: даёт готовую матрицу решений, а не заменяет подбор
  уникального бренда».

Честное предупреждение: «сделай красиво» **уже принадлежит** `web-visual-polish`.
Авто-роутинг решает по полному тексту `description`; разведение держится на
формулировках «создать новое / подобрать под задачу» vs «отполировать
существующий CSS» — это работает, но **хрупко**. После создания **обязательно**
прогнать триггер-тест (2.6) и подтвердить:
- «сделай красиво» на существующей странице → `web-visual-polish`;
- «подбери шрифты и палитру под детский магазин» / «сделай лендинг с нуля» /
  «оформи обложку альбома» → `design-matrix`.

### 2.4. Тело SKILL.md, матрица и чек-лист

**Тело SKILL.md (коротко):**
1. Назначение + ссылки на `references/matrix.md`, `references/cover-art.md`,
   `references/quality-checklist.md`.
2. Порядок работы: (а) определить архетип задачи по предметной области/аудитории/
   жанру; (б) взять из матрицы стартовые типографику/палитру/сетку/плотность/
   моушн; (в) адаптировать под конкретику (матрица — стартовая точка, не догма;
   для уникального бренда — связка с `frontend-design`); (г) прогнать чек-лист
   перед сдачей.
3. Инварианты floor-качества: кириллица с фолбэком, контраст AA, видимый
   `:focus-visible`, `prefers-reduced-motion`, адаптив 320/768/1440 без
   горизонтального скролла, длина строки текста < 70–80ch, ≤4 размеров текста на
   экране, один основной акцент.

**`references/matrix.md` — минимум 8 архетипов.** Для каждого: шрифтовая пара
(заголовок + текст, **обязательно с кириллическим фолбэком** в стеке — урок из
`specs/cat-toys-premium-fonts.md`), палитра (кол-во цветов, настроение,
температура, 1 акцент), сетка/плотность, радиусы/тени, моушн, и строка «когда НЕ
подходит». Набор:

1. **B2B / SaaS-дашборд, аналитика** — нейтральный гротеск (Inter / IBM Plex
   Sans + кириллица), сдержанная палитра, 1 акцент, плотная сетка, малые радиусы,
   тихие тени, минимум моушена.
2. **Маркетинговый лендинг / промо** — выразительный дисплейный заголовок +
   читаемый санс, 1 смелый акцент + нейтрали, крупный hero, один
   оркестрированный момент моушена.
3. **Премиум / люкс / бутик** — высококонтрастный сериф (Cormorant / Playfair +
   кириллический сабсет и серифный фолбэк) + гуманистический санс, много воздуха,
   приглушённая/тёмная палитра с метью, крупный масштаб, сдержанный моушн.
4. **Редакционный / блог / длинный контент** — читаемый сериф или гуманистический
   санс, колонка < 70–80ch, спокойная палитра, щедрый line-height, почти без
   декора.
5. **Детский / игровой / развлекательный** — округлый жирный санс, яркая палитра
   (контроль контраста), крупные скругления, игривый, но не бесконечный моушн.
6. **Техно / developer tools / терминал** — моно для акцентов/данных, тёмная
   тема, один неоновый акцент (осторожно с контрастом), плотная сетка.
7. **Финансы / здоровье / доверие** — консервативный санс, холодная палитра,
   высокий контраст, минимум декора, крупные тапабельные зоны.
8. **Портфолио / креатив / агентство** — экспериментальная/дисплейная
   типографика, крупный масштаб, асимметрия — зона связки с `frontend-design`.

Также добавить короткий блок **«презентации/слайды»**: крупный контраст
заголовок/текст, ≤6 строк на слайд, одна мысль на слайд, единая сетка полей,
консистентная типографика между слайдами.

**`references/quality-checklist.md` — проверяемый чек-лист** (любой архетип):
семантика; адаптив 320/768/1440 без горизонтального скролла/обрезки; базовый
текст ≥16px; контраст AA (4.5:1 текст, 3:1 крупный); видимый `:focus-visible`;
`prefers-reduced-motion`; переходы только по конкретным свойствам (не
`transition: all`); кириллица во всех шрифтах (есть фолбэк с кириллицей); ≤4
размеров текста на экране; длина строки < 70–80ch; один основной акцент; цвет не
единственный сигнал состояния.

### 2.5. Обложки альбомов — типографика поверх изображения (честная механика)

**Критично и без магии.** SKILL.md — это **инструкция**, он сам пиксели не
двигает и загруженный PNG не редактирует. «Доработка обложки» технически — это
**рендер типографического/композиционного оверлея поверх картинки**, а не
ретушь растра. Поэтому скилл работает так:

**Что технически делает скилл (прописать в `references/cover-art.md`):**
- **Основной путь (рекомендуемый): SVG/HTML-оверлей.** Скилл инструктирует модель
  сгенерировать разметку (предпочтительно **inline SVG**, либо HTML+CSS), где
  подгруженное изображение — фон (`<image>` в SVG по пути/URL или data-URI), а
  поверх — типографика (артист, название, доп. надписи), работающая как слой.
  Результат — артефакт/файл, который рендерится в картинку (экспорт PNG/SVG
  средствами рантайма или скриншотом). **SVG предпочтителен**, т.к. даёт точный
  контроль позиционирования текста, безопасных зон и экспорт без потерь.
- **Запасной путь: точные параметры для ручной доводки.** Если автоматический
  рендер недоступен, скилл отдаёт конкретику: шрифт (с жанровой мотивацией),
  кегль, трекинг, цвет и обводка/подложка текста, координаты и выравнивание,
  безопасные зоны — чтобы пользователь довёл в своём редакторе.

**Запрещено обещать:** «скилл сам отредактирует/отретуширует загруженный PNG»,
менять содержимое растра, «улучшить» саму фотографию. Скилл добавляет
**типографический и композиционный слой поверх**, не трогая исходные пиксели.

**Контент `references/cover-art.md` (гайд):**
- **Иерархия «артист / название»:** что крупнее, где ставить, как не спорить с
  фокусом изображения.
- **Настроение по жанру (мини-матрица):** эмбиент/неоклассика (тонкий сериф или
  лёгкий гротеск, минимализм, воздух, приглушённо); хип-хоп (жирный гротеск/
  дисплей, высокий контраст, смелая композиция); метал (агрессивный дисплей/
  блэклеттер, высокий контраст, текстура); поп (чистый геометрический санс,
  яркий акцент, центрированная/симметричная композиция); электроника/техно
  (моно/техно-гротеск, неон, сетка); инди/фолк (гуманистический санс или
  рукописный акцент, тёплая палитра). Для каждого — 1 строка «чего избегать».
- **Контраст текста на изображении:** подложка/плашка, полупрозрачный слой,
  обводка/тень, проверка читаемости на светлых и тёмных участках фото; цель —
  читаемость заголовка в худшем месте картинки.
- **Безопасные зоны и форматы:** квадрат 1:1 (стриминг, ориентир экспорта
  ≥3000×3000 для дистрибуции), отступы от краёв, запас под обрезку/аватар-кроп;
  не ставить критичный текст в углы/края.
- **Кириллица:** шрифт обложки обязан поддерживать кириллицу, если название/
  артист на русском; иначе — фолбэк.

### 2.6. Как создавать (механика skill-creator) и размещение

Реализация — через скилл `anthropic-skills:skill-creator`:
1. Инициализировать пакет его процедурой; разместить в
   **`~/.claude/skills/design-matrix/`** (глобально), `references/` рядом.
2. Заполнить `description` по формуле skill-creator, прогнать его **оптимизацию
   описания под авто-триггер** + триггер-тест (ниже).
3. Вынести матрицу, cover-art и чек-лист в `references/`.
4. В отчёте зафиксировать результат триггер-теста.

## 3. Ограничения и зависимости

- Скилл — чистый Markdown (SKILL.md + references). Кода/сборки/денег нет.
- Авто-триггер в **Claude Code** читается из ФС (`~/.claude/skills`) по
  `description` — надёжно.
- **Claude Design (канвас) — нужен пользователю, но поддержка не подтверждена.**
  Claude Code и Claude Design — разные рантаймы. Нет подтверждения, что Design
  подтягивает файловые `SKILL.md` из `~/.claude/skills`. Вероятно, для стороны
  claude.ai/Design скилл нужно загружать через её собственный механизм «Skills»
  (если Design вообще поддерживает кастомные скиллы). **Отдельная задача:**
  проверить поддержку кастомных скиллов в Claude Design и, если есть, загрузить
  пакет туда; результат зафиксировать в отчёте. Не выдавать «работает в Design»
  без проверки.
- Экспорт обложки в растр зависит от рантайма (возможность отрендерить SVG/HTML в
  PNG). Если рантаймом не поддерживается — работает запасной путь (параметры для
  ручной доводки).

## 4. Риски, цена и открытый вопрос

**Цена:** низкая — текст. Риски не в деньгах:
1. **Коллизия триггеров с `web-visual-polish`** по «сделай красиво» — митигируется
   формулировкой `description` и обязательным триггер-тестом; остаточная
   хрупкость фиксируется в отчёте.
2. **Claude Design может не подтянуть файловый скилл** — ожидание «везде
   автоматически» для канваса может не сбыться без отдельной загрузки/проверки.
3. **Обложки: скилл не редактирует растр сам** — только оверлей/параметры. Если
   пользователь ждёт ретушь самой фотографии, это вне возможностей скилла (нужен
   графический инструмент/редактор).
4. **Матрица-шаблон** может провоцировать шаблонные решения — в теле прописать,
   что матрица = стартовая точка, уникальный бренд = `frontend-design`.

**Открытый вопрос пользователю (ТЗ дописано в рабочем варианте, но уточнить):**
В каком формате отдавать доработанную обложку по умолчанию — (а) inline SVG с
фоновым изображением (точный контроль, экспорт в PNG средствами рантайма), (б)
HTML+CSS-артефакт, или (в) только текстовые параметры для ручной доводки в
стороннем редакторе? По умолчанию в ТЗ заложен путь **(а) SVG-оверлей** с
запасным **(в)**. Если пользователь предпочтёт иное — поправить `cover-art.md`.

      `references/quality-checklist.md`) через механику `skill-creator`,
      размещён **глобально**.
- [ ] `description` на русском, по формуле skill-creator, с триггер-фразами
      (включая «сделай красиво» в сценарии создания/подбора и фразы про обложки) и
      **явной границей** относительно `web-visual-polish` и `frontend-design`.
- [ ] Триггер-тест пройден и задокументирован: «сделай красиво» на существующей
      странице → `web-visual-polish`; «подбери шрифты/палитру под <тип>», «сделай
      красиво с нуля/по ТЗ», «оформи обложку альбома» → `design-matrix`.
- [ ] `references/matrix.md` — ≥8 архетипов (+ блок презентаций/слайдов), у
      каждого: шрифтовая пара с кириллическим фолбэком, палитра, сетка/плотность,
      радиусы/тени, моушн, строка «когда НЕ подходит».
- [ ] `references/cover-art.md` — гайд по типографике поверх обложки: иерархия
      артист/название, жанровая мини-матрица настроения, контраст текста на фото,
      безопасные зоны/форматы (1:1, экспорт), кириллица. **Явно** описана
      техническая механика (SVG/HTML-оверлей или параметры для ручной доводки) и
      **явно** указано, что скилл НЕ редактирует исходный растр сам.
