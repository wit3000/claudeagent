# ТЗ: редакторский конвейер для ChatGPT (копирайтер, редактор, свежий читатель)

Статус: **версия 1, октябрь 2026.** Факты о платформе ChatGPT собраны веб-поиском по вторичным источникам. Официальные страницы OpenAI (help.openai.com, developers.openai.com, learn.chatgpt.com) из среды разработки не открылись. Всё, что не подтверждено первоисточником, помечено «не проверено», и под это заложены консервативные допущения.

## 0. Контекст

### 0.1. Что хочет пользователь

На claude.ai у пользователя работает конвейер из трёх навыков: `seo-copywriter-ru`, `seo-editor-ru`, `seo-fresh-reader-ru` (исходники — `editorial-skills/`, ТЗ — `specs/seo-editorial-pipeline.md`). Нужен такой же конвейер в ChatGPT: ТЗ SEO-специалиста на входе, готовая статья и блок «Заметки к сдаче» на выходе. Плюс отдельные режимы «вычитай», «приведи в порядок смысл», «свежий взгляд».

Качество текста — то же, что на claude.ai: правила фразы (`_shared/phrase.md`), смысловая редактура (`_shared/meaning.md`), стоп-лист, свод правок редактора (`_shared/self-check.md`), нормы 2026 года (`_shared/norms-2026.md`), скрипты `lint_text.py`, `text_stats.py`, `outline.py`.

### 0.2. Ключевые решения (обязательны к прочтению)

1. **Один источник правды.** Тексты навыков не копируются в отдельную папку для ChatGPT. Сборка берёт `editorial-skills/` и накладывает поверх небольшой набор адаптаций для ChatGPT (раздел 2.3). Правка правила в `_shared/` попадает в обе платформы одной командой.
2. **Основной путь — нативные навыки ChatGPT (Skills).** По найденным источникам ChatGPT поддерживает навыки в формате папки с `SKILL.md` (frontmatter `name` и `description`, папки `scripts/`, `references/`, `assets/`). Навыки подгружаются поэтапно: сначала имя и описание, полный `SKILL.md` — когда навык выбран. Вызов — автоматически по описанию или через `@`. Это тот же формат Agent Skills, что на claude.ai, поэтому навыки переносятся почти без изменений.
3. **Запасной путь — Project в ChatGPT** (инструкции + файлы), если у пользователя нет доступа к Skills на его тарифе. Сборка выпускает и этот пакет (раздел 2.5).
4. **Custom GPT не используем.** По данным нескольких источников OpenAI выводит Custom GPT из обращения 11 декабря 2026 года, а на личных тарифах (Free, Go, Plus, Pro) новые GPT создавать уже нельзя. Строить на этом новое решение бессмысленно.
5. **Plugins (бывшие Apps) не используем в MVP.** По источникам плагины объединяют навыки, файлы и подключённые приложения и предназначены для распространения. Пользователю нужен личный конвейер, и навыков для него достаточно. Плагин — возможный следующий шаг (раздел 4).

### 0.3. Что известно о платформе

| Факт | Значение | Статус |
|---|---|---|
| Формат навыка | папка с `SKILL.md`; обязательны `name` и `description`; необязательны `scripts/`, `references/`, `assets/` | вторичные источники (OpenAI Academy и документация для разработчиков в выдаче поиска); страницы не открылись |
| Загрузка навыка | поэтапная: имя и описание → полный `SKILL.md` при выборе | вторичные источники |
| Вызов | автоматически по `description` или `@имя` | вторичные источники |
| Тарифы со Skills | данные расходятся: один источник — бета на Free, Go, Plus и Pro по странице цен на 16.10.2026; справка — только Business, Enterprise, Healthcare, Edu | **не проверено** → пользователь проверяет сам (2.1) |
| Установка навыка из zip | **не проверено**. В конце 2025 года навыки лежали в песочнице Code Interpreter в `/home/oai/skills` | собираем zip; путь загрузки уточняется при приёмке |
| Песочница для скриптов | Code Interpreter: Python 3 со стандартной библиотекой, без сети | подтверждено несколькими источниками для Code Interpreter; для навыков — **не проверено** |
| Путь к файлам навыка в песочнице | исторически `/home/oai/skills/<имя>/` | **не проверено** → навык ищет свои скрипты поиском (2.3.3) |
| Навык вызывает другой навык | нет данных | **не проверено** → конвейер описан текстом, как на claude.ai |
| Custom GPT | вывод из обращения 11.12.2026; на личных тарифах создание закрыто | несколько вторичных источников и упоминание справки OpenAI |
| Лимит инструкций Project | нет данных | **не проверено** → инструкции ≤ 8000 знаков (2.5) |
| Лимит файлов Project | нет данных | **не проверено** → не больше 10 файлов (2.5) |
| Память ChatGPT (Memory) | переносит сведения между чатами | известное поведение → влияет на свежего читателя (2.4) |

Источники: [Simon Willison о навыках в ChatGPT, декабрь 2025](https://simonwillison.net/2025/Dec/12/openai-skills/), [OpenAI Academy: Using skills](https://openai.com/academy/skills/), [ChatGPT Skills: тарифы](https://swapbiswas.com/blog/chatgpt-skills/), [Virtualization Review о выводе Custom GPT](https://virtualizationreview.com/articles/2026/09/28/openai-to-retire-custom-gpts-replace-them-with-plugins.aspx), [справка OpenAI: Custom GPT retirement FAQ](https://help.openai.com/en/articles/20001519-custom-gpt-retirement-and-migration-faq).

### 0.4. Допущения

- **A1.** Модель в ChatGPT выполняет инструкции `SKILL.md` и читает файлы из `references/` так же, как Claude, если в `SKILL.md` прямо сказано, какой файл когда прочитать.
- **A2.** Скрипты используют только стандартную библиотеку Python (проверено: `lint_text.py`, `text_stats.py`, `outline.py` импортируют только её) и запускаются в песочнице.
- **A3.** Веб-поиск в ChatGPT доступен модели во время работы навыка. Если нет, фактчек работает в режиме без поиска, как на claude.ai.
- **A4.** Навыка `seo-text-review-ru` в ChatGPT нет: это личный навык пользователя на claude.ai, его исходников в репозитории нет. Редактор работает без него и пишет об этом в заметках, как сейчас. Если пользователь пришлёт zip этого навыка, его можно добавить отдельной задачей.

## 2. Задача

### 2.1. Шаг 0: проверка доступа (делает пользователь, до реализации не блокирует)

В README для ChatGPT (2.6) первым пунктом стоит проверка: есть ли в настройках ChatGPT раздел навыков (Skills) и можно ли загрузить свой навык. От ответа зависит путь установки: Skills (2.2–2.4) или Project (2.5). Реализуются оба пути: сборка дешёвая, а выбор делает пользователь.

### 2.2. Новая цель сборки `--target chatgpt`

**Требование.** В `scripts/build_editorial_skills.py`:

- аргумент `--target {claude,chatgpt,all}`, по умолчанию `claude` (текущее поведение);
- для `chatgpt` выход по умолчанию — `dist/chatgpt-skills/` (навыки и zip, меняется через `--out`) и `dist/chatgpt-project/` (пакет Project, 2.5, меняется через `--project-out`); к обеим папкам применяется та же защита `unsafe_out_dir`;
- `all` собирает обе платформы;
- `--check` проверяет исходники и для `chatgpt` дополнительно применяет адаптации в памяти, не записывая файлы. Если какая-то замена не нашла исходный текст (2.3.1), это ошибка с именем файла и началом искомой строки;
- zip для ChatGPT детерминированные, как сейчас: та же `write_zip`;
- проверки `validate_skill` действуют и для ChatGPT: имя `^[a-z0-9-]{1,64}$`, `description` ≤ 1024 знаков, без `<` и `>`, тело `SKILL.md` ≤ 500 строк, все упомянутые `references/…` и `scripts/…` существуют. Запрет на слова `anthropic` и `claude` в имени остаётся.

Порядок сборки для ChatGPT: копия навыков → общие файлы (`SHARED_FILES`) → дополнительные общие файлы для ChatGPT (2.3.2) → адаптации текста (2.3.1) → вставка блока о запуске скриптов (2.3.3) → валидация → zip.

### 2.3. Адаптации для ChatGPT

Все адаптации хранятся в `editorial-skills/_chatgpt/`. Папка начинается с `_`, поэтому `skill_dirs` её не считает навыком. Состав:

```
editorial-skills/_chatgpt/
  replacements.json        # точечные замены текста (2.3.1)
  run-scripts.md           # блок «Как запускать скрипты» (2.3.3)
  gpt-habits.md            # типичные ошибки текстов ChatGPT (2.3.4)
  PROJECT_INSTRUCTIONS.md  # инструкции для пути через Skills (2.4)
  PROJECT_FALLBACK.md      # инструкции для пути через Project (2.5)
  README.md                # установка в ChatGPT (2.6)
```

#### 2.3.1. Замены текста

`replacements.json` — список объектов `{"file": "<путь внутри навыка, например seo-fresh-reader-ru/SKILL.md>", "old": "…", "new": "…"}`. Сборка применяет их по порядку. `old` должен встречаться в файле **ровно один раз**, иначе сборка падает с ошибкой (так замены не устаревают молча после правки исходников).

Минимальный набор замен (Лупа находит точные строки в текущих файлах):

| Файл | Что заменить | На что |
|---|---|---|
| `seo-fresh-reader-ru/SKILL.md` | «открой **новый чат вне Project** — знания Project с ТЗ автоматически попадают в…» | «открой **временный чат** (Temporary chat) или новый чат вне проекта при выключенной памяти — иначе память и файлы проекта с ТЗ попадут в контекст…» |
| `seo-copywriter-ru/SKILL.md` | «из первичных источников по протоколу фактчека навыка `seo-editor-ru`: файл `seo-editor-ru/references/fact-check.md`» | «из первичных источников по протоколу фактчека: `references/fact-check.md`» |
| `seo-copywriter-ru/SKILL.md`, `seo-editor-ru/SKILL.md` | строки о том, что навык «подключён, если он есть в списке твоих навыков в этом диалоге» | «подключён, если он доступен тебе в этом чате (в списке навыков или через `@`)» |
| все `SKILL.md` и `references/output-format.md` | упоминания «claude.ai», если найдутся при реализации | нейтральное «чат» |

Проверка после замен: в собранных файлах для ChatGPT нет подстрок `claude.ai`, `Claude` и `Customize > Skills`, кроме цитат в примерах, если они там есть (тест 6).

#### 2.3.2. Дополнительные общие файлы для ChatGPT

- `seo-editor-ru/references/fact-check.md` → в `seo-copywriter-ru/references/fact-check.md`. Копирайтер не может полагаться на путь к файлам другого навыка: где лежат навыки в ChatGPT, не проверено.
- `_chatgpt/gpt-habits.md` → в `references/gpt-habits.md` копирайтера и редактора. В «Что прочитать перед работой» у копирайтера и в список проходов у редактора добавляется строка о нём (через замены 2.3.1).

Сборка проверяет, что файлы с этими путями не закоммичены в исходники навыков, — так же, как `forbidden_in_source`.

#### 2.3.3. Как запускать скрипты

Путь к папке навыка в песочнице не проверен, поэтому относительный вызов `python3 scripts/lint_text.py article.md` может не сработать. Сборка вставляет в `SKILL.md` копирайтера и редактора, сразу после заголовка первого раздела с командой `python3 scripts/…`, содержимое `_chatgpt/run-scripts.md`:

1. Сохрани статью в файл `/mnt/data/article.md` (или в рабочую папку песочницы).
2. Найди папку навыка: `find / -name lint_text.py -path "*<имя навыка>*" 2>/dev/null | head -1`. Если поиск ничего не нашёл, переходи к шагу 5.
3. Запускай скрипты по полному пути: `python3 <папка>/scripts/lint_text.py /mnt/data/article.md`.
4. Скрипты работают без сети и без сторонних библиотек.
5. Если песочница недоступна или скрипт не запускается, выполни проверку вручную по стоп-листу, `phrase.md` и `meaning.md` и напиши в заметках: «Скрипты не запускались, проверка выполнена вручную».

Если `SKILL.md` не содержит команды `python3 scripts/`, сборка падает: значит, исходник поменялся и место вставки надо пересмотреть.

#### 2.3.4. Типичные ошибки текстов ChatGPT (`gpt-habits.md`)

Новый справочный файл: ошибки, которые чаще встречаются у моделей OpenAI и пока не описаны в `_shared/`. Каждая ошибка — в том же формате, что `phrase.md`: ошибка → почему плохо → как исправить, с примерами «было → стало». Минимум:

- **Переоформление.** Жирный шрифт внутри абзацев, списки там, где нужна связная мысль, заголовки на каждые два абзаца. Правило: жирный — только для ключей, если это требует ТЗ; список — по `style-rules.md`, правило 10.
- **Эмодзи и восклицательные знаки** в информационном тексте.
- **Хвосты ассистента** в ответе и в статье: «Если хотите, могу…», «Надеюсь, это поможет», «Вот статья:», «Итог:». Ответ начинается с H1 и заканчивается блоком заметок, без предложений помощи.
- **Злоупотребление длинным тире** как универсальной связкой (усиливает правило `phrase.md`, раздел 5).
- **Английские кальки синтаксиса**: «Это позволяет вам…», «Когда дело доходит до…», «Будь то X или Y», «В мире, где…», «Ключ к успеху — …».
- **Тройки и симметричные пары**: «быстро, удобно, выгодно», «не только… но и…» в каждом абзаце.
- **Финальное резюме-пересказ** перед заметками.

`lint_text.py` для этих паттернов **не меняется** в этой задаче: шаблоны из `gpt-habits.md` вносятся в линтер отдельной задачей после приёмки, когда станет видно, какие ошибки ChatGPT делает на самом деле (раздел 4).

### 2.4. Путь через Skills: инструкции и порядок работы

`_chatgpt/PROJECT_INSTRUCTIONS.md` — текст, который пользователь вставляет в инструкции Project в ChatGPT или, если проектов не использует, в персональные инструкции (Custom instructions). Основа — `editorial-skills/PROJECT_INSTRUCTIONS.md`, отличия:

- упоминание навыков через `@seo-copywriter-ru` и т. п. как запасной способ вызвать навык, если ChatGPT не выбрал его сам;
- строка: «Перед работой открой SKILL.md нужного навыка и файлы из его references, которые он называет на текущем шаге. Не работай по памяти о навыке»;
- запрет хвостов ассистента (2.3.4) в формате ответа;
- свежий читатель: «в этом чате независимость условная; для настоящего свежего взгляда — временный чат без памяти».

Размер — не больше 8000 знаков (тест 6). Если не помещается, сокращаются пояснения, а не правила формата ответа и фактов.

Порядок конвейера, формат ответа, правила фактов и оригинальности — те же, что на claude.ai. Расхождения в поведении между платформами допустимы только в способе запуска скриптов и в изоляции свежего читателя.

### 2.5. Запасной путь: пакет для Project

Если навыков на тарифе пользователя нет, конвейер собирается из инструкций и файлов проекта. Сборка кладёт в `dist/chatgpt-project/`:

| Файл | Содержимое |
|---|---|
| `instructions.txt` | `_chatgpt/PROJECT_FALLBACK.md`, ≤ 8000 знаков: роли, порядок конвейера, формат ответа, жёсткие правила фактов; ссылки на файлы проекта по именам ниже |
| `01-copywriter.md` | `SKILL.md` копирайтера без frontmatter, затем `craft.md`, `genres.md`, `case-balms.md`, `style-rules.md`, `tz-parsing.md`, `originality.md`, `output-format.md` — каждый под заголовком `# Файл: <имя>` |
| `02-editor.md` | `SKILL.md` редактора, `checklist.md`, `fact-check.md` |
| `03-fresh-reader.md` | `SKILL.md` свежего читателя и `protocol.md` |
| `04-rules.md` | `_shared/`: `phrase.md`, `meaning.md`, `stop-list.md`, `self-check.md`, `norms-2026.md`, `_chatgpt/gpt-habits.md` |
| `05-tz-examples.md` | `tz-examples.md` — образцы разбора ТЗ |
| `lint_text.py`, `text_stats.py`, `outline.py` | скрипты как есть |

Итого 9 файлов: `instructions.txt` вставляется в поле инструкций, остальные 8 загружаются в файлы проекта. Ссылки вида `references/craft.md` внутри склеенных файлов заменяются на «раздел „Файл: craft.md“ в 01-copywriter.md» (таблица соответствий в сборке; ссылка на неизвестный файл — ошибка сборки). Строка в инструкциях: «Скрипты лежат в файлах проекта; если Code Interpreter видит их в `/mnt/data`, запускай оттуда, иначе проверяй вручную» — доступ кода к файлам проекта **не проверен**.

`instructions.txt` проверяется на длину; превышение — ошибка сборки с числом знаков.

### 2.6. README для ChatGPT

`_chatgpt/README.md` копируется в `dist/chatgpt-skills/README.md` и `dist/chatgpt-project/README.md`. Содержание, коротко и по шагам:

1. Как проверить доступ к Skills (2.1) и какой путь выбрать.
2. Путь Skills: загрузить три zip (или распакованные папки, если ChatGPT принимает только папки — уточняется при приёмке), включить, вставить `PROJECT_INSTRUCTIONS.md`, включить веб-поиск и выполнение кода.
3. Путь Project: создать проект, вставить `instructions.txt`, загрузить 8 файлов.
4. Свежий взгляд: временный чат или выключенная память.
5. Пробный прогон: ТЗ из `tz-examples.md`, ожидаемые дефекты ТЗ в заметках — те же, что в `editorial-skills/README.md`.
6. Чего нет по сравнению с claude.ai: навыка `seo-text-review-ru`; гарантий, что скрипты запустятся.

В `editorial-skills/README.md` добавляется раздел «Сборка для ChatGPT» с командой `python scripts/build_editorial_skills.py --target chatgpt` и ссылкой на `_chatgpt/README.md`.

## 3. Ограничения и зависимости

- Python ≥ 3.11 для сборки, только стандартная библиотека (как сейчас).
- Сборка для claude.ai не меняется (раздел 1).
- `_chatgpt/` — единственное место, где живут отличия ChatGPT. Правила качества текста в `_chatgpt/` не дублируются: только адаптации платформы и `gpt-habits.md`.
- Тексты в `_chatgpt/` пишутся по правилам `phrase.md` и стоп-листа: прогон `lint_text.py` по `gpt-habits.md`, `PROJECT_INSTRUCTIONS.md` и `PROJECT_FALLBACK.md` без ошибок (примеры «было» в цитатах допустимы — проверять по предупреждениям вручную).

## 4. Риски и цена

- **Платформа меняется быстро.** Skills в ChatGPT — бета с неясными тарифами, Custom GPT выводятся, Apps переименованы в Plugins. Цена ошибки невысокая: сборка — один скрипт, тексты общие. Главный риск — потратить время на путь, недоступный на тарифе пользователя. Поэтому шаг 0 (2.1) и два пути.
- **Модель другая.** Правила написаны под поведение Claude и под ошибки, найденные в его текстах. У ChatGPT свои привычки (2.3.4). Без прогона на реальных ТЗ неясно, каких правил не хватает. Следующая задача после приёмки: три прогона по ТЗ из `tz-examples.md`, разбор ошибок, пополнение `gpt-habits.md` и шаблонов линтера.
- **Скрипты могут не запускаться.** Путь к навыку и доступ кода к файлам проекта не проверены. Деградация мягкая: ручная проверка по правилам и строка в заметках.
- **Свежий читатель слабее.** Память ChatGPT и файлы проекта снижают изоляцию. Смягчение — временный чат.
- **Объём работы.** Сборка и тесты — около дня работы кодера. Тексты `_chatgpt/` — ещё полдня. Платных API нет.
- **Альтернатива подешевле**, если пользователю достаточно одной вычитки: только путь Project с одним редактором (файлы `02-editor.md` и `04-rules.md`). Не рекомендую: конвейер теряет копирайтера и разбор ТЗ.
- **Следующий шаг (не в этой задаче):** упаковать три навыка в один плагин ChatGPT, если плагины окажутся удобнее для установки.
