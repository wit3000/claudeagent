# Design matrix

## Назначение

Этот навык — знаниевый. Он не двигает пиксели сам: он даёт модели готовую
**матрицу решений** и правила, чтобы оформление нового продукта (или подбор стиля
под задачу) начиналось не с нуля и не со случайных дефолтов, а с проверенной
стартовой точки, подходящей под предметную область, аудиторию или жанр.

Крупные блоки вынесены в `references/` — читай нужный файл по ссылке, когда
дошёл до соответствующего шага:

- `references/matrix.md` — матрица архетипов (B2B/SaaS, лендинг, премиум,
  редакционный, детский, техно, финансы/здоровье, портфолио + блок
  презентаций/слайдов): для каждого шрифтовая пара с кириллическим фолбэком,
  палитра, сетка/плотность, радиусы/тени, моушн и строка «когда НЕ подходит».
- `references/cover-art.md` — типографика и композиция поверх обложки альбома
  или изображения: иерархия артист/название, жанровая мини-матрица, контраст
  текста на фото, безопасные зоны и форматы, кириллица, честная механика
  SVG-оверлея.
- `references/quality-checklist.md` — проверяемый чек-лист качества вёрстки для
  любого архетипа.

## Когда применять

Применяй автоматически по смыслу запроса (даже без имени навыка), когда нужно
**создать новое оформление** или **подобрать стиль под задачу**: собрать лендинг,
интерфейс, артефакт, слайды или обложку с нуля либо по ТЗ; выбрать шрифты, цвета
или сетку под тип продукта, аудиторию или жанр; ответить «какой шрифт/палитра/
сетка подойдёт под <X>».

Не применяй вместо `web-visual-polish`, когда задача — **отполировать готовый
CSS уже существующего интерфейса без смены контента** (тени, spacing, состояния в
рамках только-CSS-контракта). Для уникального небанального бренда под бриф —
связка с `frontend-design`: эта матрица даёт стартовую точку, а не финальный
уникальный стиль.

## Порядок работы

1. **Определи архетип задачи** по предметной области, аудитории или жанру
   (для обложек — по жанру музыки). Если задача на стыке — возьми ближайший
   архетип как базу и отметь, что адаптируешь.
2. **Возьми стартовые параметры из `references/matrix.md`** (или из
   `references/cover-art.md` для обложек): шрифтовую пару, палитру, сетку,
   плотность, радиусы/тени, моушн.
3. **Адаптируй под конкретику.** Матрица — стартовая точка, не догма. Если нужен
   уникальный бренд, уходящий от шаблона, — разверни решение через
   `frontend-design`, а матрицу используй как опору, а не как потолок.
4. **Прогони `references/quality-checklist.md`** перед сдачей.

## Инварианты floor-качества

Независимо от архетипа держи минимальную планку (подробности и проверка — в
`references/quality-checklist.md`):

- кириллица во всех шрифтах — в стеке обязателен фолбэк, покрывающий кириллицу;
- контраст текста AA (4.5:1 основной текст, 3:1 крупный);
- видимый `:focus-visible` у интерактивных элементов;
- `prefers-reduced-motion` отключает/сокращает анимации;
- адаптив на 320/768/1440 без горизонтального скролла и обрезки контента;
- длина строки основного текста < 70–80ch;
- не больше 4 размеров текста на одном экране;
- один основной акцентный цвет.

## Граница с другими навыками

- **`web-visual-polish`** владеет сценарием «отполировать существующий CSS без
  смены контента». Если пользователь просит «сделай красиво» про уже готовую
  страницу и менять нужно только стили — это его задача, не эта. Не перехватывай.
- **`frontend-design`** отвечает за уникальный небанальный бренд под бриф. Эта
  матрица его дополняет (даёт стартовые наборы), а не заменяет: для архетипа
  «портфолио/креатив/агентство» и любого «нужно уйти от шаблона» передавай
  уникальную часть туда.
- **`artifact-design`, `dataviz`** — дизайн артефактов и графиков/палитр для
  данных; при пересечении опирайся на них в их зоне.
