# Редакторский конвейер для SEO-статей

Три навыка для claude.ai, которые вместе пишут и вычитывают SEO-статьи по ТЗ SEO-специалиста.

| Навык | Что делает | Как вызвать |
|---|---|---|
| `seo-copywriter-ru` | разбирает ТЗ, пишет статью, запускает вычитку | вставить ТЗ и написать «напиши текст по ТЗ» |
| `seo-editor-ru` | вычитка, фактчек со ссылками, правка | «вычитай», «проверь факты», «отредактируй» |
| `seo-fresh-reader-ru` | читает текст глазами неэксперта, ищет, где читатель спотыкается | «свежий взгляд», «прочитай как читатель» |

Конвейер: копирайтер → редактор → свежий читатель → один круг правок. На выходе статья и короткий блок «Заметки к сдаче» после разделителя `---`: дефекты ТЗ, источники фактов, непроверенное, объём. Блок отрезается перед публикацией.

## Автор статей в Claude Code

В этом репозитории тот же конвейер работает без zip и без claude.ai: пришлите ТЗ в сессию Claude Code, и навык `.claude/skills/avtor-statey` разберёт его, задаст уточняющие вопросы (один раунд, до четырёх), затем поручит статью агенту `avtor`, вычитку — агенту `redaktor`, свежий взгляд — агенту `chitatel` и соберёт итог. Агенты лежат в `.claude/agents/` и читают правила прямо из `editorial-skills/`.

Свежий читатель здесь изолирован по-настоящему: он получает только текст статьи. Рабочие файлы — в `articles/<дата>-<имя>/` (в git не попадают), карточки заказчиков — в `articles/_clients/`.

## Сборка

```
python scripts/build_editorial_skills.py
```

Скрипт проверяет навыки и кладёт три zip в `dist/editorial-skills/`. Только проверка, без сборки: `--check`.

Общие файлы хранятся в одном месте — `_shared/`: стоп-лист `stop-list.md`, смысловая редактура `meaning.md` (обратный план и двенадцать проверок смысла), правила фразы `phrase.md` (деятель, сочетаемость, регистр, повторы), свод правок редактора `self-check.md` и нормы на 2026 год `norms-2026.md`. При сборке они копируются в навыки копирайтера и редактора. Из навыка копирайтера в навык редактора копируются `craft.md`, `case-balms.md`, `text_stats.py`, `lint_text.py` и `outline.py`. Копии в папки навыков не коммитятся, сборка это проверяет.

## Скелет текста для смысловой правки

```
python3 editorial-skills/seo-copywriter-ru/scripts/outline.py article.md
```

Скрипт выводит дерево заголовков, первую фразу и объём каждого абзаца, долю каждого раздела в тексте и помечает разделы короче 300 знаков. По этому скелету копирайтер и редактор строят обратный план — мысль каждого абзаца одной фразой — и проверяют смысл по `_shared/meaning.md`.

## Механическая проверка стиля

```
python3 editorial-skills/seo-copywriter-ru/scripts/lint_text.py article.md
```

Скрипт находит стоп-фразы, слова не из темы, просторечие, обезличенные глаголы без деятеля («берут», «выбирают» — категория «кто действует?»), рубленый ритм, абзацы без связок, повторы слов и однокоренных слов в предложении, в соседних предложениях и между заголовком и первой фразой, шаблонные карточки, лишние оговорки и ошибки типографики. Код выхода 1 — есть ошибки. Связность и уместность слов он оценивает приблизительно: окончательное решение — за медленным чтением.

Пример: `tests/fixtures/balms_bad.md` — текст, который заказчик не принял, `tests/fixtures/balms_rewrite.md` — он же, переписанный по правилам `craft.md`.

## Требования к аккаунту claude.ai

- План, в котором доступны навыки (Skills).
- Включено «Code execution and file creation»: без него навыки не работают, а объём статьи считается приблизительно.
- Включён веб-поиск. Без него фактчек не может ничего подтвердить: все внешние факты получат маркер `[не проверено: …]`.

## Установка

1. Соберите zip командой выше.
2. На claude.ai откройте Customize > Skills и загрузите три файла: `seo-copywriter-ru.zip`, `seo-editor-ru.zip`, `seo-fresh-reader-ru.zip`.
3. Включите каждый навык. Навыки подключаются к аккаунту, а не к отдельному Project.
4. Создайте Project и вставьте текст из `PROJECT_INSTRUCTIONS.md` в поле инструкций проекта. Инструкции задают порядок конвейера и формат ответа.

5. Проверьте, что в настройках аккаунта включены веб-поиск и «Code execution and file creation».
6. Сделайте пробный прогон: новый чат в проекте, вставьте ТЗ из `seo-copywriter-ru/references/tz-examples.md` и напишите «напиши текст по ТЗ». Ответ должен начинаться с `# H1` из ТЗ, а в «Заметках к сдаче» должны быть дефекты ТЗ, разобранные в том же файле: морская доставка, «мультифокальные», Оренбург, расхождение слов и знаков.

**SEO-ТЗ не кладите в знания Project.** Вставляйте ТЗ прямо в чат. Знания проекта попадают в каждый чат проекта, и тогда свежий читатель увидит ТЗ даже в новом чате.

В знания Project можно положить **карточки компаний-заказчиков**: цены «от», адреса складов, преимущества, сроки, контакты. Один файл на компанию, только проверенные данные. Тогда копирайтер возьмёт данные оттуда, а не поставит заглушку `[нужны данные: …]`.

Одна статья — один чат. Длинная переписка с несколькими статьями путает контекст: правила из одного ТЗ начинают влиять на другое.

## Навык seo-text-review-ru

Редактор первым этапом применяет навык `seo-text-review-ru`, если он подключён: рубленые факты, ультимативный тон, приписывание мотивов, «удобно», подводки к ссылкам, пересказ источников. Правила этого навыка в редакторе не повторяются.

- Если у вас есть zip `seo-text-review-ru`, загрузите его так же: Customize > Skills, загрузить, включить.
- Если его нет, редактор выполнит остальные проходы и напишет в заметках: «Навык seo-text-review-ru не подключён: проверка по его чек-листу не выполнена». Вычитка в этом случае неполная.

## Ограничение свежего взгляда

В одном чате независимость свежего читателя условная: модель уже видела ТЗ и черновик. Протокол навыка смягчает это, но не устраняет.

Для настоящего свежего взгляда:

1. Откройте **новый чат вне Project**.
2. Вставьте только текст статьи, без ТЗ и заметок.
3. Напишите «свежий взгляд».

Другой вариант — сервис Triple-Pass Text Reviewer из этого репозитория: его Pass 3 First-Time Reader работает изолированным вызовом модели.

## Полные отчёты

По умолчанию отчёты не выводятся, чтобы ответ состоял из статьи. Чтобы их увидеть, напишите следующим сообщением:

- «покажи отчёт редактора» или «покажи правки» — правки с цитатами «было → стало»;
- «покажи смысловой разбор» — обратный план статьи и исправленные смысловые ошибки;
- «покажи замечания читателя» — сбои с цитатами и ответы на три вопроса.

Если длинный ответ обрезался, напишите «продолжи».
