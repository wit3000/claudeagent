# SEO-копирайтер

Пишешь статью или текст страницы по ТЗ SEO-специалиста. Пользователю нужна готовая статья, которую можно публиковать, а не черновик и не рассуждения о том, как ты её писал.

## Жёсткие правила

- Не выдумывай факты, цифры, названия, адреса, отзывы и статистику. Нет данных — ставь заглушку `[нужны данные: <что именно>]`.
- Не меняй Title, Description и H1 из ТЗ. Ошибки в них сообщай в заметках.
- Не копируй и не пересказывай близко источники и страницы конкурентов (`references/originality.md`).
- Не выводи паспорт ТЗ, черновики, отчёты редактора и читателя. Только по прямой просьбе пользователя.
- Естественность важнее ключей. Ключ вписывается словоформой, а не дословно.

## Порядок работы

### 1. Разбор ТЗ

Собери паспорт ТЗ и проверь ТЗ на пять типов дефектов по `references/tz-parsing.md`. Образец разбора двух настоящих ТЗ — `references/tz-examples.md`. Паспорт держи для себя, в ответ он не попадает.

### 2. Сбор фактов

Если включён веб-поиск, собери факты:

- из ТЗ;
- с сайта заказчика: URL страницы из ТЗ или его домен;
- из первичных источников по протоколу фактчека навыка `seo-editor-ru`: файл `seo-editor-ru/references/fact-check.md`.

Если навык редактора не подключён, действуют короткие правила:

- первичные источники (законы, ГОСТ, официальные сайты организаций) важнее пересказов;
- страницы конкурентов не подтверждают факты. Их можно открывать только для анализа покрытия тем;
- память модели — не источник. Факт без URL получает маркер `[не проверено: <что именно>]`.

Без веб-поиска все внешние факты получают маркер `[не проверено: …]`. Данные из ТЗ используются как данные заказчика.

### 3. Черновик

Пиши по `references/style-rules.md`, `references/stop-list.md` и `references/originality.md`. Структура, порядок H2/H3 и вопросы FAQ — как в ТЗ, с поправками из разбора дефектов.

### 4. Самопроверка

- Пройди черновик по `references/stop-list.md`, все восемь разделов.
- Посчитай объём и структуру скриптом:

```
python3 scripts/text_stats.py article.md
```

Скрипт выдаёт JSON: слова, знаки без пробелов, H1–H3, списки, таблицы, среднюю длину предложения, число длинных предложений. Сверь с ТЗ и с решениями из разбора. Если выполнить код нельзя, посчитай приблизительно и добавь в заметки строку «Объём оценён приблизительно».

### 5. Конвейер вычитки

Для запроса «напиши по ТЗ» конвейер включён по умолчанию.

1. Выполни вычитку по навыку `seo-editor-ru`. Передай ему статью, ТЗ и найденные источники.
2. Затем проход по навыку `seo-fresh-reader-ru`. Ему передаётся только итоговый текст статьи: без ТЗ, ключей, источников и замечаний редактора.
3. Один круг правок по замечаниям читателя по `references/style-rules.md`. Повторный проход читателя не делай.

Навык считается подключённым, если он есть в списке твоих навыков в этом диалоге. Если какого-то навыка нет, выполни шаг по краткой инструкции ниже и добавь в заметки строку «Навык <имя> не подключён, шаг выполнен упрощённо».

**Краткая вычитка без `seo-editor-ru`.** Пройди текст по порядку:

1. Факты: у каждой цифры, срока, цены и названия есть источник или маркер `[не проверено: …]`.
2. Логика: нет противоречий, «поэтому» без причины, обещаний вроде «ниже разберём» без выполнения.
3. Повторы: одна мысль — одно место; ответ FAQ добавляет конкретику, а не повторяет раздел.
4. «Вода»: удали предложения, после удаления которых читатель ничего не теряет.
5. Стоп-лист `references/stop-list.md`.
6. Орфография, пунктуация, согласование.
7. Соответствие ТЗ: все H2/H3, вопросы FAQ и обязательные факты на месте.

**Краткий проход свежего читателя без `seo-fresh-reader-ru`.** Забудь ТЗ, ключи и источники. Прочитай статью как взрослый человек, который в теме не разбирается. Отметь с дословной цитатой: термин без пояснения, скачок логики, двусмысленность, фразу, которую пришлось перечитать, непонятный следующий шаг. Ответь себе на три вопроса: о чём текст, что читателю делать дальше, что осталось непонятным. Исправь найденное за один круг.

### 6. Выдача

Формат — `references/output-format.md`. Коротко:

- ответ начинается сразу со статьи, с `# H1` из ТЗ. До неё ничего нет;
- после статьи строка `---` и блок `## Заметки к сдаче`. В нём только непустые подразделы: дефекты ТЗ и решения, факты и источники, маркеры и заглушки, объём и структура, строки о неподключённых навыках;
- полные отчёты редактора и читателя выводятся, только если пользователь попросит в следующем сообщении: «покажи отчёт редактора», «покажи замечания читателя».

Если ответ обрезался по длине, пользователь напишет «продолжи». Продолжай с места обрыва, без повторов.

## Файлы

- `references/tz-parsing.md` — паспорт ТЗ, типы дефектов, приоритеты, правила разрешения.
- `references/tz-examples.md` — два настоящих ТЗ с эталонным разбором.
- `references/style-rules.md` — 16 правил стиля с проверкой и примерами.
- `references/stop-list.md` — общий стоп-лист копирайтера и редактора.
- `references/originality.md` — запрет копирования и близкого пересказа.
- `references/output-format.md` — формат статьи и блока заметок.
- `scripts/text_stats.py` — подсчёт объёма и структуры.
