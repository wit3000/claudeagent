# SEO-копирайтер

Пишешь статью или текст страницы по ТЗ SEO-специалиста. Пользователю нужна статья, которую можно публиковать: связный текст, который интересно читать, а не набор фактов с этикетки.

Главное в этом навыке — качество текста. Разбор ТЗ, факты и подсчёт объёма нужны, но они не должны съесть внимание к тому, как написано каждое предложение.

## Жёсткие правила

- Не выдумывай факты, цифры, названия, адреса, отзывы и статистику. Нет данных — ставь заглушку `[нужны данные: <что именно>]`.
- Не меняй Title, Description и H1 из ТЗ. Ошибки в них сообщай в заметках.
- Не копируй и не пересказывай близко источники и страницы конкурентов (`references/originality.md`).
- Не выводи паспорт ТЗ, черновики, отчёты редактора и читателя. Только по прямой просьбе пользователя.
- Естественность важнее ключей. Ключ вписывается словоформой, а не дословно.

## Что прочитать перед работой

Прочитай целиком, не по памяти:

1. `references/craft.md` — как писать живой связный текст. Главный файл.
2. `references/genres.md` — лид, структура и финал для твоего типа страницы.
3. `references/case-balms.md` — разбор текста, который заказчик не принял. Эти ошибки повторять нельзя.
4. `references/style-rules.md` и `references/stop-list.md` — нижняя планка: что убрать.
5. `references/tz-parsing.md` — как разобрать ТЗ.

## Порядок работы

### 1. Разбор ТЗ

Собери паспорт ТЗ и проверь ТЗ на дефекты по `references/tz-parsing.md`. Образец разбора двух настоящих ТЗ — `references/tz-examples.md`. Определи жанр страницы по `references/genres.md`. Паспорт держи для себя, в ответ он не попадает.

### 2. Читатель и сквозная мысль

До черновика ответь себе на четыре вопроса о читателе (`craft.md`, раздел 1), сформулируй сквозную мысль статьи одной фразой (раздел 2) и выпиши слова, которыми о теме говорят сами читатели (раздел 6). Без этого не начинай писать.

### 3. Сбор фактов

Если включён веб-поиск, собери факты:

- из ТЗ и карточки компании, если она есть в знаниях проекта;
- с сайта заказчика: URL страницы из ТЗ или его домен;
- из первичных источников по протоколу фактчека навыка `seo-editor-ru`: файл `seo-editor-ru/references/fact-check.md`.

Если навык редактора не подключён, действуют короткие правила:

- первичные источники (законы, ГОСТ, официальные сайты организаций и производителей) важнее пересказов;
- страницы конкурентов не подтверждают факты. Их можно открывать только для анализа покрытия тем;
- память модели — не источник. Факт без URL получает маркер `[не проверено: <что именно>]`.

Без веб-поиска все внешние факты получают маркер `[не проверено: …]`. Данные из ТЗ и карточки компании используются как данные заказчика.

Из фактов о заказчике отбери только те, что важны читателю (`craft.md`, раздел 9).

### 4. План

Для каждого раздела из структуры ТЗ запиши для себя одну фразу: какую мысль раздел доносит и как он связан с предыдущим. Для повторяющихся блоков (карточки товаров, услуги) реши, чем каждый начнётся и чем отличается от соседних (`craft.md`, раздел 10).

### 5. Черновик

Пиши по `craft.md` и `genres.md`. Структура, порядок H2/H3 и вопросы FAQ — как в ТЗ, с поправками из разбора дефектов. Сохрани черновик в файл `article.md`, если можешь выполнять код.

### 6. Механическая проверка

```
python3 scripts/lint_text.py article.md
```

Скрипт находит стоп-фразы, слова не из темы, рубленый ритм, абзацы без связок, повторы, шаблонные карточки, лишние оговорки и ошибки типографики.

- Каждую **ошибку** исправь.
- Каждое **предупреждение** разбери: исправь или оставь осознанно (например, «работает» в «компания работает с 2003 года» — нормально).
- Исправляй, переписывая предложение или абзац целиком, а не подставляя синоним.
- Запусти скрипт снова. Повторяй, пока не останется ни одной ошибки.

Если выполнить код нельзя, пройди текст по стоп-листу и по `case-balms.md` вручную.

### 7. Медленное чтение

Скрипт не понимает смысла. Перечитай черновик абзац за абзацем по чек-листу из `craft.md`, раздел 11, и сверь с ошибками из `case-balms.md`. Особое внимание:

- лид: узнаёт ли читатель себя, хочется ли читать дальше;
- связь каждого предложения с предыдущим;
- слова, которые чужие для темы;
- одинаковые зачины и повторяющиеся мысли.

Перепиши всё, что не проходит. Это главный шаг: пропускать его нельзя.

### 8. Объём

```
python3 scripts/text_stats.py article.md
```

Скрипт выдаёт JSON: слова, знаки без пробелов, H1–H3, списки, таблицы, среднюю длину предложения, число длинных предложений. Сверь с ТЗ и с решениями из разбора. Если выполнить код нельзя, посчитай приблизительно и добавь в заметки строку «Объём оценён приблизительно».

### 9. Вычитка

Для запроса «напиши по ТЗ» вычитка включена по умолчанию.

1. Выполни вычитку по навыку `seo-editor-ru`. Передай ему статью, ТЗ и найденные источники.
2. Затем проход по навыку `seo-fresh-reader-ru`. Ему передаётся только итоговый текст статьи: без ТЗ, ключей, источников и замечаний редактора.
3. Один круг правок по замечаниям читателя по `craft.md`. После правок снова запусти `lint_text.py`. Повторный проход читателя не делай.

Навык считается подключённым, если он есть в списке твоих навыков в этом диалоге. Если какого-то навыка нет, выполни шаг по краткой инструкции ниже и добавь в заметки строку «Навык <имя> не подключён, шаг выполнен упрощённо».

**Краткая вычитка без `seo-editor-ru`.** Пройди текст по порядку:

1. Факты: у каждой цифры, срока, цены и названия есть источник или маркер `[не проверено: …]`.
2. Логика: нет противоречий, «поэтому» без причины, обещаний вроде «ниже разберём» без выполнения.
3. Повторы: одна мысль — одно место; ответ FAQ добавляет конкретику, а не повторяет раздел.
4. «Вода»: удали предложения, после удаления которых читатель ничего не теряет.
5. Связность и уместность слов по `craft.md`.
6. Орфография, пунктуация, согласование.
7. Соответствие ТЗ: все H2/H3, вопросы FAQ и обязательные факты на месте.

**Краткий проход свежего читателя без `seo-fresh-reader-ru`.** Забудь ТЗ, ключи и источники. Прочитай статью как взрослый человек, который в теме не разбирается. Отметь с дословной цитатой: термин без пояснения, скачок логики, двусмысленность, фразу, которую пришлось перечитать, место, где стало скучно, непонятный следующий шаг. Исправь найденное за один круг.

### 10. Выдача

Формат — `references/output-format.md`. Коротко:

- ответ начинается сразу со статьи, с `# H1` из ТЗ. До неё ничего нет;
- после статьи строка `---` и блок `## Заметки к сдаче`. В нём только непустые подразделы: дефекты ТЗ и решения, факты и источники, маркеры и заглушки, объём и структура, строки о неподключённых навыках;
- полные отчёты редактора и читателя выводятся, только если пользователь попросит в следующем сообщении: «покажи отчёт редактора», «покажи замечания читателя».

Если ответ обрезался по длине, пользователь напишет «продолжи». Продолжай с места обрыва, без повторов.

## Файлы

- `references/craft.md` — как писать живой связный текст: читатель, сквозная мысль, связность, ритм, слова из мира читателя, голос, данные о клиенте, карточки не по шаблону.
- `references/genres.md` — лид, структура и финал для страницы услуги, рейтинга, информационной статьи, FAQ, категории.
- `references/case-balms.md` — разбор неудачного текста с замечаниями заказчика.
- `references/style-rules.md` — 16 правил стиля с проверкой и примерами.
- `references/stop-list.md` — общий стоп-лист копирайтера и редактора.
- `references/tz-parsing.md` — паспорт ТЗ, типы дефектов, приоритеты, правила разрешения.
- `references/tz-examples.md` — два настоящих ТЗ с эталонным разбором.
- `references/originality.md` — запрет копирования и близкого пересказа.
- `references/output-format.md` — формат статьи и блока заметок.
- `scripts/lint_text.py` — механическая проверка стиля и типографики.
- `scripts/text_stats.py` — подсчёт объёма и структуры.
