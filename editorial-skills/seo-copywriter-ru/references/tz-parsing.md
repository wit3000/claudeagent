# Разбор SEO-ТЗ

Сначала разбор, потом текст. Паспорт и список дефектов нужны для работы и в ответ не выводятся. В блок заметок попадают только решения по дефектам: «что в ТЗ → что сделано» (см. `output-format.md`).

Образцы разбора двух настоящих ТЗ — в `tz-examples.md`.

## 1. Паспорт ТЗ

Заполни все поля. Если поле в ТЗ не задано, пиши «не задано». Не догадывайся и не подставляй типичное значение.

| Поле | Что записать |
|---|---|
| URL страницы | адрес из ТЗ; по нему же ищется сайт заказчика |
| Тип страницы | услуга, блог, категория или другое |
| Тема и основной интент | одна фраза: что читатель хочет узнать или сделать на странице |
| Title, Description, H1 | дословно. Только для чтения, не переписываются |
| Тезис | главная мысль страницы из ТЗ |
| Своя деталь | факт о заказчике, которого нет у конкурентов, и где его упомянуть |
| ЦА | кто читает и что сравнивает |
| Тон | как задано в ТЗ |
| Структура | дерево H2/H3 в порядке ТЗ; у каждого блока задача и обязательные факты |
| FAQ | список вопросов и требования к ответам |
| Обязательно покрыть | темы и факты, которые ТЗ требует включить |
| Отличия от конкурентов | чего нет у конкурентов и что должно быть у нас |
| Объём | слова, знаки без пробелов, диапазон |
| Число H2/H3, списков, таблиц | как в ТЗ |
| Ключи | топ-слова, биграммы, триграммы, TF-IDF; отдельно ключи, которые нельзя вписать дословно |
| SEO-рекомендации | требования к вхождениям и оформлению |
| Конкуренты (URL) | список; нужен только для анализа покрытия тем |
| Источники | ссылки, которые дал SEO-специалист |
| Термины без пояснений | ТЗ разрешает не объяснять |
| Термины с пояснением | ТЗ требует объяснить |

## 2. Пять типов дефектов

Проверь ТЗ на каждый тип. Найденный дефект решается по разделу 4 и попадает в заметки.

### Тип 1. Шаблонный остаток

Элемент из шаблона другой страницы: другой город как основной объект, другой вид транспорта на странице про конкретный вид, чужая услуга.

Как найти: сверь каждый блок структуры с H1 и URL. Если элемент не про тему страницы, это остаток.

Пример: на странице ж/д-перевозок Москва — Красноярск «География доставки» начинается с «Оренбург и Оренбургская область».

### Тип 2. Опечатка или неверный термин

Как найти: термин, которого нет в отрасли или который значит другое. Проверь по словарю или первичному источнику.

Пример: «мультифокальные перевозки» вместо «мультимодальные».

### Тип 3. Числовое противоречие

Три проверки:

1. Заявленное число заголовков сверяется с деревом структуры.
2. Слова и знаки сверяются по формуле: слова × 6,5 ≈ знаки без пробелов. Расхождение больше 25% — дефект. Пример: 550 слов дают около 3 600 знаков, а в ТЗ 6 000.
3. Объём делится на блоки. Если на H2 или H3 выходит меньше 40 слов или на ответ FAQ меньше 2 предложений, объём в структуру не помещается.

### Тип 4. Нереализуемое требование без данных

ТЗ требует цену «от», срок, адрес, «5 причин выбрать нас», но данных нет ни в ТЗ, ни на сайте заказчика. Сайт проверяется веб-поиском, если поиск включён. Если выключен, данных нет.

### Тип 5. Требование ломает норму языка или естественность

Примеры: «включать ключевые слова примерно по 3 раза, особенно в начале абзацев»; ключ «штрих код» при норме «штрихкод»; ключ без предлога «перевозки Москва Красноярск».

## 3. Приоритеты при конфликте

Побеждает требование с бо́льшим приоритетом:

1. Фактическая достоверность и законность. Ничего не выдумывать.
2. Тема, тип страницы и основной интент (H1, тезис, URL).
3. Явная структура: перечень H2/H3, обязательные факты, вопросы FAQ.
4. Количественные рекомендации: слова, знаки, число заголовков, списков и таблиц.
5. Ключевые слова и SEO-рекомендации по вхождениям.

Каждое разрешённое противоречие — строка в заметках.

## 4. Правила разрешения

**Шаблонный остаток.** Удали или замени на то, что соответствует теме. Если элемент можно оставить второстепенным без искажения темы, оставь в этой роли. Пример: авиа и авто на странице про ж/д — строки сравнительной таблицы, а не разделы.

**Опечатка в термине.** Пиши нормативный термин.

**Метаданные.** Title, Description и H1 не меняй, даже если в них ошибка. Ошибку сообщи в заметках.

**Число заголовков против структуры.** Побеждает структура.

**Объём против структуры.** Сохрани структуру полностью. Возьми минимально достаточный объём: не меньше 40 слов на блок H2/H3, ответ FAQ — 2–4 предложения. Фактический объём укажи в заметках. Если структура требует вдвое больше слов, чем ТЗ, можно влить H3 без самостоятельного содержания в родительский H2. Только с отметкой в заметках.

**Слова против знаков.** Если в ТЗ есть диапазон слов, выбери объём внутри диапазона, который ближе всего к цели по знакам. Нет диапазона — приоритет у числа слов.

**Нет данных заказчика.** Поставь заглушку `[нужны данные: <что именно>]`, например `[нужны данные: цена от, ₽ за 1 т]`. Не выдумывай. Блок «Почему выбирают нас» строится только из подтверждённых фактов: подтверждено три причины — пиши три, остальные отметь заглушкой.

**Ключ против нормы языка.** Пиши нормативную форму: «штрихкод», а не «штрих код». Вхождение засчитывается словоформой. В заметках отметь, что точная форма ключа не использована. Требование «по 3 раза в начале абзацев» выполняй, пока текст читается естественно. Естественность важнее.

## 5. Что попадает в заметки

Одна строка на дефект, в формате «что в ТЗ → что сделано»:

- «Морская доставка в блоке „Варианты доставки“ → убрана, к маршруту не относится».
- «487 слов при 4 H2, 10 H3 и 7 вопросах FAQ → структура сохранена, 1 240 слов».
- «Ключ „штрих код“ → в тексте „штрихкод“, точная форма не использована».

Паспорт, рассуждения и таблицу дефектов целиком не выводи.
